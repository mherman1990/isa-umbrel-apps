# Bean Brief functional audit — 2026-10-04 (Phase 0, read-only)

**Scope:** v1.38.0 (`src/`, app id `isa-polibrief`). The audit asks which parts of the tool are actually updating, and which data reaches which outputs. No application code was changed. Phase 0 adds two things:

- `scripts/audit-freshness.mjs`, a read-only, rerunnable freshness report.
- Its test, `test/audit-freshness.test.js` (9 tests). The full suite is now 409 tests, all passing; the baseline was 400/400.

## 0. What is verified here, and what needs the Pi

This session had the code but not the Pi's SQLite store, its `/data/watchlist.json` or its `.env`.

- **Verified from the code:** every structural finding below. Each cites `file:line`, and was re-read after two independent sweeps of all 33 adapters and every consumer.
- **Needs the Pi:** every live value — last-success timestamps, ages, key presence, last errors and token counts. These come from running the script on the Pi. I have **not** filled any live number in by guesswork.

**Run it on the Pi (works with the current 1.38.0 image; nothing to install).** The script only needs `better-sqlite3` and the adapter sources, and both are already in the image:

```bash
# on the Pi (umbrel@umbrel.local)
curl -fsSL https://raw.githubusercontent.com/mherman1990/isa-umbrel-apps/claude/modest-mayer-eona8h/scripts/audit-freshness.mjs -o /tmp/audit-freshness.mjs
docker cp /tmp/audit-freshness.mjs isa-polibrief_web_1:/app/scripts/audit-freshness.mjs
docker logs isa-polibrief_web_1 > /tmp/pb.log 2>&1 && docker cp /tmp/pb.log isa-polibrief_web_1:/tmp/pb.log
docker exec isa-polibrief_web_1 node scripts/audit-freshness.mjs --log /tmp/pb.log > ~/bean-brief-audit.md
```

`--json` gives machine output. `--now <ISO>` pins the clock for reproducible runs.

**How the script stays read-only:**
- It opens the database with `{ readonly: true, fileMustExist: true }`.
- It never imports `src/store.js`, which runs `CREATE`/`ALTER TABLE` on import, and never imports any adapter.
- It prints key **presence** only.
- It creates no files.

The test proves that the database file and the WAL are byte-identical after a CLI run.

## 1. Headline findings

1. **Storylines are most likely failing by truncation, and the failure feeds itself.**
   - `generateStorylines` caps output at **4,500 tokens** (`pipeline.js:2032`).
   - The 1.30.0 schema (`pipeline.js:2593-2675`) makes one thread ≈ **720 output tokens** at its own field guidance.
   - The prompt asks for 3–7 threads, plus "any existing thread whose state changed", out of 10 prior threads it is fed. That crosses the cap at about 6–7 threads.
   - A truncated JSON body fails `JSON.parse` and is logged as "a genuinely quiet window, not a parse failure" (`pipeline.js:2047`). The function then returns `null` before `pruneStorylines` and before writing `storylines_meta`.
   - So the same 10 stale threads stay on screen and stay in the next prompt, and the next call truncates again.
   - The script names this as the verdict when `token_usage` shows storylines calls at the cap. §3 lists the alternative causes and their signatures.
2. **No cached panel records a failed or empty attempt.** `news_digest`, `market_intel`, `market_cards` and storylines write state only on success. Every `null` return and every thrown error leaves the previous success on screen.
   - Storylines has **no staleness badge at all** (`server.js:1105`).
   - The other three show one only after 4 days (`STALE_PANEL_DAYS`).
   - Truncated prose in the digest and intel panels is stored as if complete.
3. **Item sources added after install are silently not collected.**
   - `seedDataDir()` copies `watchlist.json` only when it is absent (`server.js:2958-2971`).
   - `collect.js:39-43` skips any adapter with no watchlist entry.
   - The Sources page shows the same adapter as on (`server.js:731`).
   - On an install seeded before a source shipped (e.g. `congress_hearings`, added in 1.22.0), that source has never run. The script lists every adapter missing from the live watchlist.
4. **Per-source errors are not persisted anywhere durable.**
   - `/logs` is a 500-line in-memory ring buffer (`server.js:42-51`), lost on every restart.
   - The only durable failure record is the list of layer *labels* in `brief_runs.missing_layers`, and that is written **only on runs that produce a brief**. Quiet runs store a bare `sources_failed` count (`pipeline.js:696`).
   - Fourteen series adapters swallow errors silently and return `[]`; four more log a line first, and `wasde` does so for some failures. Returning `[]` is recorded as neither a success nor a failure (`pipeline.js:206-216`), so a dead feed reads as "nothing new" until the 18-day series-staleness rule trips.
5. **Two of the four Member Brief inputs are not fit for member use yet.**
   - CFTC fetches **soybeans only**: no meal, no oil.
   - Barge freight is an **unfiltered average of `price_per_ton` across all locations** on each date (`agtransport.js:50-51`).
   - The soy:corn signal reads NASS **Iowa monthly prices received**.
   - A new-crop Nov/Dec ratio can only be computed from `cme_settlements`, which is off.
   - Details in §4.3.
6. **The calendar data ends on 2026-12-10.** The `calendar_events.2026.json` and `policy_events.2026.json` file names are hard-coded (`calendar.js:18,32`). Mid-December, "Coming up", the pre-report trigger and the Member Brief's "What to watch" will go quiet.

- **Fetch cadence:** every enabled adapter is fetched on both the AM and PM runs, so fetch is expected every 12 h and flagged STALE after 24 h.

## 3. Storylines root cause

### 3.1 Your four observations against the code

| Observation | Verified? | Evidence |
|---|---|---|
| Runs only on the AM edition, wrapped in a try/catch that only logs | ✅ | `pipeline.js:493-499` |
| `storylines_meta.generatedAt` is written only on success; `null` without touching meta when < 3 items or zero threads | ✅ | `pipeline.js:1981`, `:2046-2049`, `:2095` |
| `pruneStorylines(30)` only runs inside a successful generation | ✅ | `pipeline.js:2094` |
| The panel shows the old success date as current | ✅ | `server.js:1105`; storylines is not in `cachedAgeDays`' map (`pipeline.js:1910`), so it gets no badge |

**Not on your list: the cap.** `max_tokens: 4500` (`pipeline.js:2032`) against a schema that grew in 1.30.0 by six per-thread fields:
- `stateChange`
- `whatIsNew`
- `whatIsUnchanged`
- `openQuestions`
- `nextExpectedEvent`
- `materiality`

Size estimates:
- **Before 1.30.0:** the release notes measured ~2.9k output tokens per call (CHANGELOG 1.30.0).
- **After 1.30.0:** I measured a realistic schema-shaped thread (5 timeline entries with URLs) at ~2,380 characters, or ≈ 720 tokens:

| Threads | Output tokens (est.) |
|---|---|
| 5 | ≈ 3,600 |
| 6 | ≈ 4,300 |
| 7 | ≈ 5,000 — **over the cap** |

The structured-outputs comment (`pipeline.js:2022-2026`) and the log line (`:2047`) both assume the schema guarantees a parseable body. **That only holds when the model stops on its own (`stop_reason: end_turn`).** A `max_tokens` stop cuts the JSON mid-object. `stop_reason` is never checked here, and it is not stored in `token_usage`.

**Why it would persist rather than recur:**
- Prune never runs, so the 10 threads stamped 9/1 remain the "previous state" block in every later prompt.
- The 21-day item window keeps refreshing, so each morning's input pushes the model toward continuing many threads.
- The ↻ Refresh button cannot break the loop: it calls the same function, and maps every `null` to *"Not enough recent items to cluster into storylines yet"* (`server.js:3169`). That notice is wrong for a truncation.
- Waste so far: ≈ $0.10 per failed call (~11.8k in / 4.5k out on Sonnet at the `pricing.js` list rates), so ≈ $3.30 over 33 mornings.

### 3.2 How to confirm on the Pi

The script's **"Storylines — root-cause evidence"** section evaluates these in order and prints the first that matches. Its 14-day schedule grid also shows AM/PM run status and each day's storylines call (`TRUNC` or the output token count).

| Hypothesis | DB signature | Script verdict |
|---|---|---|
| AM edition not firing | no `brief_runs` row with `edition='am'` after `storylines_meta.generatedAt` | `NO AM RUN …` |
| Truncation (most likely) | `token_usage` rows with `purpose='storylines'` after that date, all with `output_tokens ≥ 4,410` (98% of the cap) | `TRUNCATION: …` |
| Zero threads | storylines calls exist, output well below the cap | `Model called but returned zero threads …` |
| < 3 items | no calls; 21-day relevant official + news < 3 | `NULL RETURN …` |
| Exception (API error, model id, auth) | AM runs exist, no storylines `token_usage` rows (the throw happens before `recordUsage`) | `… THREW before recordUsage …` (plus the last `Storylines skipped:` line if `--log` is given) |

Two notes on the evidence:
- **Restarts erase the log, not the DB.** A container restart or an Umbrel update erases both the `/logs` ring buffer and `docker logs`, so the database is the evidence that survives.
- **Scheduled runs are labelled `manual`.** `brief_runs.trigger` is always `"manual"` even for scheduled runs (`server.js:560` hard-codes it), so the script uses `edition` and time rather than `trigger`.

### 4.2 Broken links

**Dangling references** (a consumer depends on something that isn't there):
- **No literal series key in `src/` outside the adapters is missing from what the adapters produce.** The key-level references are clean.
- **Provenance names a source that doesn't exist:** `provenance.js:53` lists `govinfo` as a primary source, but there is no `govinfo` adapter.
- **Challenger context is always blank:** `pipeline.js:1625` reads `s.history?.n/min/max`, but snapshot rows carry no `history` field (`store.js:549-572`). Every line prints `? observations, range ?–?`, so the Challenger's `history_sufficient` check judges blind.
- **`missingSeriesPrefixes` is never passed** (`pipeline.js:709-720` → `brief.js:183`). A failed market layer stays in the card evidence menu until it ages into staleness.

**Produced but mislabeled or mixed:**
- The `soy_corn_ratio` chart is titled "(Iowa)" but plots both the NASS Iowa monthly ratio and the CBOT nearby daily ratio (`server.js:2327`).
- The `biofuel_feedstock` chart mixes lbs with `eia:soyoil-rd-share` (%).
- `nass:us:soyoil-stocks` / `-production` are commented as driving oil share (`usda_nass.js:114`). They don't: `crush.js` never reads them.

**Edition routing:**
- `/run` accepts `farmer` and `pulse` (`server.js:3405`).
- `triggerRun` treats only four presets as memos (`:556`), so those two editions run the **full policy pipeline** under that name.
- `sendFarmerEmail` (`deliver.js:232`) and `newsrank.pushCandidates` have no callers.
